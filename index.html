01 · Flagship

PhishGuard AI

A Flask app that scores a pasted email for phishing. With no API keys it stays on built-in rules. When keys are set, a scan can also ask Groq for a JSON risk judgment and check extracted links with VirusTotal. The live app is deployed on Vercel.

  • Gmail connects with the read-only scope. A scan loads up to 15 inbox messages and reads the body — plain text, or HTML with the tags removed — rather than the snippet alone. The full body is not stored.
  • History stores which engine produced the row: AI, Rules, AI + VT, or Rules + VT. Groq sees the first 6,000 characters. Link checks keep the first five http(s) URLs. The default model name in the code is openai/gpt-oss-20b, and GROQ_MODEL can replace it.
  • Registration rejects a password shorter than 8 characters and answers a duplicate email or username with one generic message. Logout is a POST with the CSRF token. Failed logins are limited to five a minute for the submitted email and five a minute for the client IP. Gmail tokens are encrypted before they are stored.
  • Unset DATABASE_URL means SQLite. A Postgres URL is what the app expects on Vercel.

02

Network IDS

A live packet monitor in Python and Scapy. It sniffs one interface and alerts on three rules: a port scan when one host sends TCP SYN packets to 10 or more unique ports, an ICMP flood at 50 packets from one source, and an SSH brute-force attempt at 5 SYN packets to port 22. A whitelist skips trusted addresses. Each alert is printed and appended to ids_log.json as one JSON object per line, with a timestamp, type, source IP, and detail.

Scripts in the repo call the SSH, ICMP, and whitelist logic directly. I documented it as a beginner build of seven days, and I used Wireshark while developing it.

  • Python
  • Scapy
  • Wireshark

03 · Earlier

Phishing detector

An earlier Flask app for checking an email or a URL. A rule scorer looks for urgency language, requests for passwords or payment details, hosts written as IP addresses, long URLs, and similar signals. A second path loads pickled scikit-learn Random Forest models for the email text and for the URL. Training uses a small hand-written set of example emails and URLs, not a public corpus.

URL checks can also consult URLhaus, Google Safe Browsing when an API key is set, and a local block list. Scans are stored in SQLite and listed on a history page. ReportLab can write a PDF, except when the Vercel environment variable is set, where that export is turned off. /api/predict returns JSON. This repository has no README.

  • Flask

  • SQLite

04 · Academic

Reinforcement-learning adaptive IDS

Academic project under the CyberChef-Aidoo GitHub account. I am not the sole author, and I don’t claim this repository as mine alone. The README calls it research from Accra Technical University. The only public commit author on the repository is that account.

The public code is an in-development scaffold. A Scapy sniffer prints packet summaries. The rule functions for port scans, ICMP floods, and SSH brute force, and the feature extractor, still raise NotImplementedError. The Gymnasium environment’s actions are allow or alert, and its step function returns zeros. The train and evaluate scripts are stubs. Requirements list Gymnasium, Stable-Baselines3, and PyTorch as a planned integration.

On my CV I describe my part as a custom detector for suspicious traffic, rule-based checks for port scans and ICMP floods with structured alert logging, and reinforcement-learning concepts aimed at adapting those rules and reducing false positives. The working port-scan, ICMP-flood, SSH, and JSON log rules under my own account are the Network IDS project above.
